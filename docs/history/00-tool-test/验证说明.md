# 婚礼 AI 视频样片验证

结论：现有工具已经跑通「照片 → AI 动态镜头 → 中文旁白 → 完整视频」；正式婚礼大屏仍需提高源视频清晰度并审核人物一致性。

验证日期：2026-11-17。本次使用用户现有订阅与公开素材，未购买新订阅或补充积分。本文件记录一次实际运行结果，不代表平台永久套餐权益。

## 交付内容

`wedding-demo-1080p.mp4`：34 秒、16:9、1920×1080、30 fps，照片片头和片尾、三段真实生成式视频、MiniMax 中文旁白、本地程序合成配乐。仅为风格和能力验证，不是已获新人验收的婚礼成片。成片文件保存在本地，未随公开仓库发布。

## 适合沿用的工作流与 Skill

照片整理与人物参考 → 逐镜头提示词 → Flow/Grok 生成短镜头 → 逐帧挑选 → MiniMax 旁白 → Remotion 统一包装与混音 → 导出及现场播放检查。

可采用官方 [Remotion Agent Skills](https://www.remotion.dev/docs/ai/skills)：涵盖创作、排版、字幕和渲染，支持 Codex。它解决剪辑包装规范，不能替代模型额度、人物一致性检查或照片授权。本轮没有安装新的全局 Skill。

## 目前真正欠缺的环节

1. 人物一致性：两家模型均出现表情、脸部和手部细节变化。真实新人照片需要按脸型、五官、手部、服装逐镜审核，不能只看是否生成成功。
2. 高清源素材：本次 Grok 原片只有 400p；Flow 为 720p 生成后升至 1080p。正式大屏需更多高质量源镜头，提升导出画布本身不会恢复细节。
3. 叙事与镜头多样性：本次只有两张相近照片。正式片建议收集生活照、合影、婚纱照及关键故事，按相识、相伴、约定组织，而非重复同一动作。
4. 成本和重试管理：本次 Flow 单镜头批准 24 点；实际成本随模型、时长、重试变化。MiniMax 视频额度目前阻塞。先使用已跑通的组合，不必立即再买订阅。
5. 现场交付：需确认屏幕比例、分辨率、播放设备与音量；目前未在婚礼大屏或音响上验收。声音只做了文件与技术检查，不宣称现场听感通过。

## 复现与验证范围

源码 src/index.tsx、渲染入口 render.cjs、配乐脚本 src/score.py，以及 assets/、evidence/ 目录都保存在本地制作目录，未随公开仓库发布。下列命令仅记录当时的运行步骤，无法在本仓库直接执行。渲染时借用本机既有的 Remotion 依赖，不是可直接异机运行的独立安装包。

```bash
python src/score.py
ffmpeg -v error -i assets/music.wav -codec:a libmp3lame -q:a 2 assets/music.mp3
fnm exec --using=22.22.0 node render.cjs
ffprobe -v error -show_streams -show_format -of json wedding-demo-1080p.mp4
ffmpeg -v error -i wedding-demo-1080p.mp4 -f null -
```

五个关键帧检查覆盖片头、两段 Grok、Flow 和片尾。中文显示完整、没有可见文字越界；Grok 画面较软、部分源镜头头顶余量小，保留为模型效果证据。源素材与关键帧保留在本地制作目录。


最终文件检查通过：34.048 秒、1920×1080、30 fps、H.264 视频、48 kHz 双声道 AAC 音频，文件 33,900,348 字节。FFmpeg 全片解码完成 1020 帧并以状态 0 退出；音频峰值 -9.8 dB、平均 -25.1 dB，没有数字削波。未进行现场播放和现场听感验收。
